# P9-SDLC-SYNTHETIC-v1 — E9 SDLC recommendation agreement (synthetic AI-generated panel)

**E9 measures agreement between ReqPilot and a synthetic AI-generated expert-panel
simulation. It is an engineering benchmark, not independent human-expert validation.**

| Property | Value |
|---|---|
| Benchmark id | `P9-SDLC-SYNTHETIC-v1` |
| Measures | E9 (Phase 0 O.1): ReqPilot's top-ranked SDLC candidate vs a blind panel's |
| Panel | **Five AI-generated expert personas** (`panel_personas.json`). Not real people, not real experts |
| Cases | 12 synthetic financial-sector projects, two per domain: digital banking, loan processing, payment systems, fraud detection, insurance, regulatory reporting |
| Generated by | Anthropic Claude ("sonnet" model tier) as independent Claude Code sub-agents, one fresh context per call, no tools, no file access — the case writer once, each persona once (`generation_prompts.md`) |
| Blinding | The panel prompts contained only the cases, the persona, the instructions and the candidate list. No panellist saw ReqPilot's rules, weights, factor scores, ranking, explanation or recommendation, any expected answer, another panellist's answer or the aggregate |
| System under test frozen first | ReqPilot's SDLC ruleset (`sdlc_rules.yaml` 1.0.0, canonical sha256 in `manifest.json`) and its hand-computed tests were fixed **before** the cases or the panel were generated |
| Frozen | 2026-09-25, **before ReqPilot was run on any case**; every file's canonical sha256 is in `manifest.json` |
| Real data | None. Every project, name and figure is fictional |
| Review | Not reviewed by the project author at freeze time; not independently reviewed; not expert-validated (`REVIEW_SHEET.md`) |

## What E9 is, and what this benchmark can and cannot say

Phase 0 O.1: *"E9 — SDLC recommendation agreement — Top-ranked model vs a blind expert
panel — ≥ 3 experts judging **before** seeing system output."* `[PS §19]` The problem
statement adds that the recommendation "can be evaluated by comparing it with decisions
made by experienced software architects and project managers".

A real human panel is not available to this project. This benchmark substitutes a
**synthetic AI-generated panel**. That keeps the E9 *protocol* — several independent
judges, each deciding before and without seeing the system's output — but not its
*meaning*: the judges are language-model simulations of experts, so

- the panel is synthetic; its members are AI-generated personas; it is not composed of
  real experts and it is not independently validated;
- it was generated for engineering evaluation;
- **E9 here measures agreement with a synthetic expert simulation, not agreement with
  real-world expert judgement**, and the result must not be presented as proof of
  real-world SDLC recommendation accuracy;
- the panel and ReqPilot's coefficients may share the same textbook view of SDLC models
  (both ultimately come from general software-engineering knowledge), so agreement may
  overstate what an independent human panel would show; disagreement is more informative
  than agreement.

## Files

| File | Contents |
|---|---|
| `cases.jsonl` | 12 cases: id, title, domain, narrative, and the approved-record facts (counts and a risk list with likelihood/impact) |
| `panel_personas.json` | The five personas: perspective and evaluation criteria |
| `panel_responses.jsonl` | 60 panel judgements verbatim (5 personas × 12 cases): full ranking of the 7 candidates, preferred candidate, rationale, key factors, confidence 1-5 |
| `panel_aggregate.json` | The deterministic panel aggregate per case, computed from the responses before any comparison |
| `generation_prompts.md` | The exact prompts, and what was (and was not) given to each generator |
| `REVIEW_SHEET.md` | What a reviewer must check |

## Candidates

`waterfall`, `v_model`, `spiral`, `agile`, `devsecops`, `agile_v_model_hybrid`,
`agile_devsecops_hybrid` — architecture L.1 (`[PS §14]`'s models and the two hybrids it
names). The panel saw a neutral one-line description of each.

## Aggregation (deterministic; no model is asked "which wins")

- **Borda count** over each panellist's full ranking: 6 points for first … 0 for seventh.
- Panel ranking: Borda score descending; ties by first-place votes, then the fixed
  candidate order above.
- **Plurality**: the candidate(s) with the most first-place votes.
- **Consensus strength**: the share of panellists whose first choice is the Borda winner.
- **Kendall's W**: concordance of the five rankings (1 = identical).

## Protocol

```
python -m scripts.run_p9_eval --benchmark data/gold/p9_sdlc_synthetic_v1 \
    --out docs/evaluation/p9-sdlc-synthetic-v1
```

1. Verify every file against `manifest.json`; re-derive the panel aggregate and require it
   to equal `panel_aggregate.json`.
2. For each case run ReqPilot's **deterministic** pipeline with the product's own code:
   severities from the approved P7 matrix, the I.6 risk aggregates (P7's formula
   function), the P9 factor derivation, the MCDA and the rule pass. No model call: the
   bounded LLM factor proposals and the LLM explanation are not part of E9.
3. Report: **E9 = top-1 agreement** (ReqPilot's first = the panel's Borda first), plus
   top-1 within the panel's top two, agreement with the plurality, how many panellists
   preferred ReqPilot's first, mean Kendall tau / Spearman rho / pairwise order agreement
   against the panel ranking, and every disagreement case.
4. **No target** (O.1: targets for E2–E9 come from measured behaviour). The result is a
   first measurement.

## Freeze rule

v1 is frozen. After ReqPilot's results were observed nothing in this directory may
change; no label is edited to improve agreement and ReqPilot is not tuned against it. A
correction becomes `P9-SDLC-SYNTHETIC-v2`.
